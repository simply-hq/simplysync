# SimplySync: inputs → transformations → outputs

SimplySync is easiest to reason about as several pipelines joined by durable
boundaries. The local SQLite commit completes before network work; the relay is
optional and stores only authenticated ciphertext plus routing metadata.

<Callout id="scope" tone="info">

This map covers only the `simplysync` repository. Application domain logic and
sibling products are outside the boundary. Source and conformance tests are
authoritative when prose differs. The concrete outbox/table diagrams describe
the canonical TypeScript engine; Swift and Kotlin preserve the wire and LWW
contracts but use a different native local-state pipeline.

</Callout>

### The critical local transaction

<AnnotatedCode
  id="atomic-row-outbox"

  annotations={[
    { lines: "1-6", label: "Durable boundary", note: "With an engine-minted unique HLC, the row and intent commit together. Caller-supplied `updatedAt` values must not be reused as event IDs." },
    { lines: "3-5", label: "Local-only branch", note: "`{ local: true }` deliberately omits the outbox while still updating local rows, tabs, and queries." },
    { lines: "8-10", label: "After commit", note: "Sealing/network work is kicked asynchronously; sibling tabs and reactive readers are updated from the committed local result." },

The pending `payload_json` is temporarily readable inside the same trusted local
database as the row. `sealPendingOutbox()` replaces that intent with an
AES-GCM envelope before push; relay selection explicitly excludes unsealed rows.

<Callout id="relay-limit" tone="warning">

End-to-end encryption protects confidentiality and integrity, not availability.
A relay can delay, reorder, omit, or delete real events. LWW convergence and
authenticated decryption prevent it from inventing an accepted application row.

</Callout>

### Compatibility invariants

- For normal engine-minted event IDs, the local row and non-local replication
  intent commit atomically. A caller-supplied `updatedAt` must be unique per
  emitted event because it is the outbox primary key.
- The relay receives only sealed envelopes and encrypted blob chunks.
- `eventId` equals the payload HLC; relay pagination uses its own monotonic
  server sequence.
- Whole-row LWW applies only a strictly newer incoming HLC; equality is a no-op.
- Unknown schema versions/tables and authenticated future HLCs are deferred;
  malformed or mismatched events are terminal for that event.
- The TypeScript engine keeps exact acknowledgement state for every configured
  relay; native ports use per-relay event-ID high-water metadata. Every engine
  gives a newly added relay a current-row backfill.
- Protocol derivation labels, canonical JSON, AAD shape, HLC encoding,
  stream-ID input, blob format, and conformance vectors are frozen wire data.

<Callout id="sharp-boundaries" tone="warning">

Database export is not a read transaction: pause writes and sync while exporting
if the backup must be self-consistent. The snapshot omits outbox state and blob
chunk bytes, so keep the original encrypted blob store available. Also, only a
browser leader seals; a follower's pending payload remains in its in-memory
SQLite copy until promotion first persists it and then starts leader sealing.

</Callout>
