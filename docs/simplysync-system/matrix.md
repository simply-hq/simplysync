# SimplySync pipeline matrix

This is the scan-first view of SimplySync. Each row starts with an input and
ends at the durable state or observable output that becomes the next pipeline's
input. The implementation and tests linked in the last column are authoritative.

Rows describing pending plaintext, seven `_sync_*` tables, exact per-relay
acknowledgements, queries, or browser tabs are the canonical **TypeScript
engine**. Swift and Kotlin share the protocol and convergence rules but use the
native divergence row below for their local pipeline.

> **TypeScript device/relay trust boundary:** application rows and
> `_sync_outbox.payload_json` are plaintext inside the local SQLite trust
> boundary. `envelope_json = ''` is the durable **plaintext-pending** marker
> committed with a non-local write. Sealing later fills `envelope_json` with an
> AES-GCM envelope; it does not send or expose `payload_json`. Only the sealed
> envelope crosses the network, and the relay stores ciphertext plus routing
> metadata. The local outbox row is removed only after every configured relay
> has acknowledged it.

## Three invariants to retain while reading

1. **Local success does not depend on the network.** A validated write commits to
   local SQLite first; replication and retries operate on durable local state.
2. **Plaintext-pending is local, never relay-visible.** The marker makes the
   synchronous row transaction crash-safe; the asynchronous seal is mandatory
   before push.
3. **Convergence is decided on clients.** Relays can paginate, deduplicate, and
   compact opaque events, but authenticated decryption, schema compatibility,
   HLC admissibility, and row-level LWW determine local state.
