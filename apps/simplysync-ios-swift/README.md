# SimplySync — native iOS (Swift) reference client

A **fully native** iOS app (SwiftUI + CryptoKit + `SQLite3`, no JavaScript) that
syncs through the SimplySync relay and interoperates with the TypeScript clients.

It ships a near-complete port of `@simplysync/engine` (`SimplySyncDemo/Engine/`):
a typed schema, a local SQLite store, typed `insert`/`update`/`upsert` mutations,
reactive SQL queries (`LiveQuery`, the SwiftUI `useQuery` analog), owner
restore/reset, and the push/pull/last-writer-wins sync loop — the same developer
experience as the React version. See the
[**Client API → Swift**](https://github.com/simply-hq/simplysync/blob/main/docs/local-first/guide.swift.md)
guide. `Engine/` builds on the `Kit/` protocol port below.

## Why a native client can interoperate

The relay only ever moves **opaque ciphertext** — it never sees keys or
plaintext. So a native client just has to speak the same protocol on the wire:

- **Identity** — derive `ownerId`, `relayAuth` (bearer token), and the AES key
  from an `sf1_` recovery key (HKDF/HMAC-SHA256) **or** a 24-word BIP39 phrase
  (SLIP-21/HMAC-SHA512). Auto-detected, exactly like `deriveIdentity`.
- **Envelope** — AES-GCM with the additional-authenticated-data set to the
  canonical-JSON header, base64url on the wire.
- **Transport** — `POST/GET /v1/events`, `Authorization: Bearer <relayAuth>`,
  integer pull cursor.

`Kit/` is a clean-room Swift port of `@simplysync/protocol` for exactly these
pieces. It is **byte-verified** against the real JS implementation (see
[Verification](#verification)).

## Layout

```
SimplySyncDemo/
  Kit/                 pure Foundation + CryptoKit — no UIKit, also runs on macOS
    Base64URL.swift    base64url
    Crypto.swift       HMAC, HKDF (deriveBytes), SLIP-21, AES-GCM
    CanonicalJSON.swift JS-JSON.stringify-compatible canonical form (the AAD)
    BIP39.swift        mnemonic -> entropy (+ 2048-word list in BIP39Wordlist.swift)
    Identity.swift     deriveIdentity (sf1_ + BIP39)
    Envelope.swift     encrypt / decrypt SyncEnvelope <-> SyncPayload
    HLC.swift          hybrid logical clock
    RelayClient.swift  push / pull against /v1/events
  Engine/              the @simplysync/engine port — builds on Kit/
    Schema.swift       typed schema DSL (id, NonEmptyString, FiniteNumber, nullable, …)
    SqliteDriver.swift SqliteDriver protocol + libsqlite3-backed SQLite3Driver
    SecureStorage.swift SecureStorage protocol + Keychain / in-memory impls
    Store.swift        DDL + system columns, _sync_* tables, writeRow, HLC clock
    Query.swift        Query<Row>, reactive cache, LiveQuery (the useQuery analog)
    RowDecoder.swift   decode SQLite rows into Decodable structs
    SyncTypes.swift    MutationResult, AppOwner, SyncState, Transport, config/deps
    SyncEngine.swift   mutations, typed queries, sync loop, owner restore/reset
  AppSchema.swift      the demo's schema + TodoRow + query
  AppModel.swift       wires createSync(deps) and owns the engine
  Views.swift          onboarding + reactive todo UI
  SimplySyncDemoApp.swift
SimplySyncDemo.xcodeproj   generated by verify/gen-xcodeproj.mjs
verify/                host-side checks (run with swiftc, no simulator needed)
```

## Run it in the Simulator

1. **Start a relay** (from the repo root). The iOS Simulator reaches your Mac at
   `localhost`:
   ```sh
   bun run relay:go         # serves http://localhost:4100
   ```
2. **Open & run** in Xcode:
   ```sh
   open apps/simplysync-ios-swift/SimplySyncDemo.xcodeproj
   ```
   Pick an iPhone simulator and hit Run. Or from the CLI:
   ```sh
   cd apps/simplysync-ios-swift
   xcodebuild -project SimplySyncDemo.xcodeproj -scheme SimplySyncDemo \
     -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 16' build
   ```
3. In the app: **Generate a new identity** (or paste an `sf1_` key / 24-word
   phrase). Add todos — they're encrypted locally and synced via the relay.

### See it interoperate

Tap **⋯ → Show recovery key**, copy it, and use the same key in another client
(a second simulator, the web playground, or the Expo app). Both become the same
owner and converge. The bundled `verify/itest` tool does this from the CLI.

## Verification

The Swift crypto is checked against vectors generated by the real JS protocol
(`verify/vectors.json`): same `ownerId`, `relayAuth`, `streamId`, and AES-GCM
ciphertext.

```sh
cd apps/simplysync-ios-swift

# 1) crypto byte-compatibility vs @simplysync/protocol
swiftc SimplySyncDemo/Kit/*.swift verify/main.swift -o /tmp/ssverify && /tmp/ssverify

# 2) live end-to-end against a running relay (push -> pull -> decrypt)
swiftc SimplySyncDemo/Kit/*.swift verify/itest/main.swift -o /tmp/ssintegration
/tmp/ssintegration http://localhost:4100

# 3) the engine: schema -> DDL, mutations, typed reactive queries, soft deletes,
#    and (with a relay URL) a live two-device push/pull/apply round-trip
swiftc SimplySyncDemo/Kit/*.swift SimplySyncDemo/Engine/*.swift verify/engine/main.swift -o /tmp/ssengine
/tmp/ssengine                       # local engine tests
/tmp/ssengine http://localhost:4100 # + live two-device interop
```

Regenerate the Xcode project after adding/removing Swift files:
```sh
node verify/gen-xcodeproj.mjs
```

## Scope (what's intentionally minimal)

- The store is real SQLite (libsqlite3) with the same schema, system columns, and
  `_sync_*` tables as `@simplysync/engine` — but queries are **raw SQL** decoded
  into `Decodable` rows, not a Kysely builder.
- Last-writer-wins per row (HLC); delete is a soft delete (`isDeleted`).
- **Not ported:** binary blobs, the encrypted DB export/import (snapshot) format,
  legacy import, and the fluent index builder.
- Column names in row `value`s should be lowercase-ASCII so canonical-JSON key
  ordering matches JS code-unit order (see `CanonicalJSON.swift`).
