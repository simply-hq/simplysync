# SimplySync — Swift package + native iOS client

The source-owned `SimplySync` Swift package and a **fully native** iOS example
(SwiftUI + CryptoKit + `SQLite3`, no JavaScript). Both use the same source files,
so the package API exercised by consumers cannot drift from the todo client.

It ships a near-complete port of `@simplysync/engine` (`Sources/SimplySync/Engine/`):
a typed schema, a local SQLite store, typed `insert`/`update`/`upsert` mutations,
reactive SQL queries (`LiveQuery`, the SwiftUI `useQuery` analog), owner
restore/reset, and the push/pull/last-writer-wins sync loop — the same developer
experience as the React version. See the
[**Client API → Swift**](../../../docs/local-first/guide.swift.md)
guide. The engine builds on the `Sources/SimplySync/Kit/` protocol port below.

## Clone and use the source

From a full SimplySync checkout:

```sh
bun run clone swift ../my-swift-sync
cd ../my-swift-sync
swift test
open apps/todolist/swift/SimplySyncDemo.xcodeproj
```

The selected repository root is a Swift package. In another Swift package, use
the clone as a local dependency:

```swift
dependencies: [
    .package(path: "../my-swift-sync"),
]
```

Then add `.product(name: "SimplySync", package: "my-swift-sync")` to the target
and:

```swift
import SimplySync

let schema = Schema([
    "todo": [
        "id": .id("todo"),
        "title": .nonEmptyString,
        "done": .sqliteBoolean,
    ],
])
let engine = createSync(
    SyncEngineDeps(
        makeDriver: { name in try SQLite3Driver(path: databasePath(name)) },
        secureStorage: KeychainStorage()
    )
)(schema, SyncEngineConfig(name: "todos"))
```

The package exposes the engine, SwiftUI-friendly `LiveQuery`, Keychain and
SQLite adapters, plus the pinned identity/envelope/HLC protocol primitives.

To create an independently named Xcode app from the same tracked client source:

```sh
sh scaffold-simplysync.sh swift my-app
open apps/my-app/MyApp.xcodeproj
```

## Why a native client can interoperate

The relay only ever moves **opaque ciphertext** — it never sees keys or
plaintext. So a native client just has to speak the same protocol on the wire:

- **Identity** — derive `ownerId`, `relayAuth` (bearer token), and the AES key
  from a BIP39 phrase (SLIP-21/HMAC-SHA512) **or** an `sf1_` recovery key
  (HKDF/HMAC-SHA256). Auto-detected, exactly like `deriveIdentity`.
- **Envelope** — AES-GCM with the additional-authenticated-data set to the
  canonical-JSON header, base64url on the wire.
- **Transport** — `POST/GET /v1/events`, `Authorization: Bearer <relayAuth>`,
  integer pull cursor.

`Sources/SimplySync/Kit/` is a clean-room Swift port of
`@simplysync/protocol` for exactly these
pieces. It is **byte-verified** against the real JS implementation (see
[Verification](#verification)).

## Run it in the Simulator

1. **Open & run** in Xcode:
   ```sh
   open apps/todolist/swift/SimplySyncDemo.xcodeproj
   ```
   Pick an iPhone simulator and hit Run. Or from the CLI:
   ```sh
   cd apps/todolist/swift
   xcodebuild -project SimplySyncDemo.xcodeproj -scheme SimplySyncDemo \
     -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 16' build
   ```
2. In the app: **Generate a new identity** (or paste a recovery phrase / legacy
   `sf1_` key). Add todos immediately; the first launch is local-only.
3. To sync, deploy the [Cloudflare relay](../../../docs/local-first/self-hosting.md)
   and enter its HTTPS URL in the app's relay field.

`SyncEngineConfig.schemaVersion` defaults to `1`. Keep it there for additive
tables/columns; bump it only for an incompatible payload-meaning change. Older
clients retain higher-version events and replay them after an upgrade declares
support.

### See it interoperate

Tap **⋯ → Show recovery key**, copy it, and use the same key in another client
(a second simulator, the TodoList web client, or the Expo app). Both become the same
owner and converge.

## Verification

The Swift crypto is checked against vectors generated by the real JS protocol
(`verify/vectors.json`): same `ownerId`, `relayAuth`, `streamId`, and AES-GCM
ciphertext.

```sh
# From the repository root: the public package surface plus the engine
# behaviours (migration, deferred replay, pruning, purge, ordering helpers).
swift test

cd apps/todolist/swift

# 1) crypto byte-compatibility vs @simplysync/protocol
swiftc ../../../Sources/SimplySync/Kit/*.swift verify/main.swift -o /tmp/ssverify && /tmp/ssverify

```

Regenerate the Xcode project after adding/removing Swift files:
```sh
node verify/gen-xcodeproj.mjs
```

## Scope (what's intentionally minimal)

- The store is real SQLite (libsqlite3) with the same schema, system columns, and
  `_sync_*` tables as `@simplysync/engine` — but queries are **raw SQL** decoded
  into `Decodable` rows, not a Kysely builder.
- Last-writer-wins per row (HLC); delete is a soft delete (`isDeleted`).
- **Not ported:** binary blobs, the encrypted DB export/import (snapshot) format,
  legacy import, and the fluent index builder.
- Column names in row `value`s should be lowercase-ASCII so canonical-JSON key
  ordering matches JS code-unit order (see `CanonicalJSON.swift`).
